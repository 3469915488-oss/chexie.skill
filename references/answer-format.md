# 回答模板

## 核心原则：四阶段生成

不要直接从 chunks 写答案。按以下步骤执行：

### 阶段一：事实抽取
从检索结果中提取结构化事实表（source_id + 原文短摘 + 事实类型），不做归纳。

### 阶段二：证据绑定
每个要写入答案的判断，必须绑定 source_id 并标注确定程度。

### 阶段三：答案生成
只使用阶段二的事实表。推荐结构：

1. 结论：用 2-4 句话直接回答当前问题。每个具体判断附 [source_id]。
2. 往年做法：列出历史上实际采用过的处理方式，每条附 [source_id] + 来源格式。
3. 曾有提案或替代方案：列出检索到的建议、争议、修改方案或不同做法，每条附 [source_id]。
4. 好处：只写证据中能支持的优点。
5. 坏处/风险：列出历史材料中出现的问题、争议、执行成本和不确定性。
6. 可参考建议：结合当前问题给出可执行建议，说明依据哪些 source_id。
7. 来源：集中列出所有引用来源，确保能回论坛核查。

### 阶段四：自检
- unsupported（无 source_id 的陈述）→ 删除
- conflict（来源冲突）→ 标注"存在不同说法"
- secondary_source（从事件索引而非原帖提取）→ 回查替换

## 来源格式

```
【版面】《帖子标题》作者 / 时间 / URL
```

例如：
```
【车协工作区】《【实践部】2026技术组考核通过名单》实践部 / 2026-05-19
https://www.chexie.net/bbs/content/index.php?bid=1&tid=10672
```

## 禁止事项

- 禁止"根据知识库记载"等模糊来源表述
- 禁止合并冲突来源
- 禁止补全检索结果中不存在的细节
- 事件索引（events/*.yaml）只能用于导航，不能作为事实依据
- 如果检索结果只有通知，没有复盘或讨论，应说明"目前只检索到通知类材料，未检索到执行后的复盘"
