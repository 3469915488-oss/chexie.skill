# 事件自动检测的已知陷阱

本文档记录在使用多维度评分算法检测历史争议事件时发现的陷阱。

## 陷阱1：引用图谱构建错误（严重）

**问题**：最初尝试用"作者共现"构建引用图谱——如果帖子A的作者名出现在帖子B中，就认为B引用了A。这导致"被引次数"维度完全失真。

**症状**：
- 几乎所有帖子的"被引次数"都显示为30+
- 无法区分真正的事件帖和日常帖子
- 排名前列的全是报名帖（因为有大量职务人员回复）

**根因**：车协论坛中有大量集体账号（理事会、主席团、文体部、实践部等），这些名字在所有版面、所有帖子的回复中都频繁出现。用作者名匹配会把"理事会在某帖下回复"误判为"该帖引用了理事会的所有帖子"。

**修复**：必须解析实际的引用结构，即 `引用自 XXX：` 这种显式标记。在 chunk 的 text 字段中搜索 `引用自\s*(.+?)\s*：` 模式，提取被引用的具体作者名，然后查找该作者发过的帖子。

**正确算法**：
```python
import re
from collections import defaultdict

# 第一步：建立"帖子-作者"映射
post_authors = defaultdict(set)  # key: "bid_tid" -> set of authors
for chunk in chunks:
    key = f"{chunk.bid}_{chunk.tid}"
    post_authors[key].add(chunk.author)

# 第二步：解析引用关系
quote_graph = defaultdict(lambda: {'cited_by': set(), 'cites': []})
for chunk in chunks:
    citing_key = f"{chunk.bid}_{chunk.tid}"
    # 提取显式引用标记
    matches = re.findall(r'引用自\s*(.+?)\s*：', chunk.text[:300])
    for quoted_author in matches:
        quoted_author = quoted_author.strip()
        # 查找该作者发过的帖子
        for target_key, authors in post_authors.items():
            if target_key != citing_key and quoted_author in authors:
                quote_graph[citing_key]['cites'].append(quoted_author)
                quote_graph[target_key]['cited_by'].add(citing_key)

# 第三步：统计被引次数
cited_counts = {key: len(info['cited_by']) for key, info in quote_graph.items()}
```

**验证**：修复后，真正的事件帖被引次数在5-15之间，日常帖子在0-3之间，维度恢复区分度。

## 陷阱2：集体作者账号的权威分膨胀

**问题**：AUTHORITY_DICT 中给"理事会"10分、"主席团"8分等，但集体账号的帖子自动获得高分，即使内容是例行公告（如"理事会关于20XX年暑期路线的决议"）。

**症状**：
- 例行公告帖因为"理事会"作者获得10分权威分
- 这些帖子本身没有争议性，但因为高分被排到前面

**修复**：权威分只是多维度之一，需要与其他维度（突发、标题信号、回复密度）组合判断。单独的高权威分不足以判定为事件。

**当前评分公式**：
```python
score = (
    min(cited * 2, 20) +           # 被引次数（上限20分）
    min(max_auth, 10) +             # 作者权威（上限10分）
    (10 if is_burst else 0) +       # 突发加分（10分）
    title_sig * 3 +                 # 标题信号词（每个3分）
    min(count // 5, 10)             # 回复数（每5回复1分，上限10分）
)
```

## 陷阱3：报名帖的回复密度误判

**问题**：报名帖（如"【25蟒山】拉练通知&报名"）通常有100+回复（职务人员签到），突发维度会触发。

**症状**：
- 报名帖因为"1天内100+回复"获得突发加分
- 但这些回复是职务人员签到，不是讨论

**修复**：在 EXCLUDE_TITLE 列表中添加报名相关关键词：
```python
EXCLUDE_TITLE = [
    '报名', '拉练通知', '预报名', '团购', '征集暑期', 
    '暑期日志', '队医日志', '押后日志', ...
]
```

## 陷阱4：跨版面 tid 污染（已在 v2 修复）

**问题**：v1 算法只按 tid 聚合，不同版面的同 tid 帖子混在一起。

**症状**：
- 行者足音 bid=2 tid=8925（"关于冬游特批的质疑"）和工作区 bid=1 tid=8925（某个旧报名帖）被合并
- 事件帖的首楼内容被报名帖覆盖

**修复**：v2 改用 `bid_tid` 作为唯一键：
```python
key = f"{chunk.bid}_{chunk.tid}"  # 如 "2_8925"
```

## 维度有效性验证

在调整评分算法后，必须验证每个维度的区分度：

| 维度 | 事件帖典型值 | 日常帖典型值 | 区分度 |
|------|-------------|-------------|--------|
| 被引次数 | 5-15 | 0-3 | ✅ 有效 |
| 作者权威 | 0-10 | 0-10 | ⚠️ 需组合判断 |
| 突发 | 10（是）/ 0（否） | 0（否） | ✅ 有效 |
| 标题信号 | 3-15 | 0 | ✅ 有效 |
| 回复数 | 5-20 | 5-10 | ⚠️ 弱区分 |

**结论**：被引次数和标题信号是最强维度，突发是二值判断，回复数和作者权威需要组合其他维度使用。

## 当前事件索引的覆盖范围

通过多维度算法，我们从 138K 条切片中识别出 14 个实质性争议事件（2011-2026），已保存在 `events/` 目录下。

**未覆盖的原因**：
- bid=3（车友宝典）和 bid=7（一技之长）的帖子主要是技术讨论（蹭碟调整、膝盖问题、买车建议），不是制度争议或人事冲突
- 这些版面的帖子在 ROUTINE 过滤阶段被排除，因为标题包含"队医日志""押后日志""考挂标准"等关键词

**如果需要扩展覆盖**：调整 ROUTINE 列表，放宽对技术讨论帖的过滤。但要注意：技术讨论帖通常不包含争议性，即使纳入也不会产生新的事件索引。
